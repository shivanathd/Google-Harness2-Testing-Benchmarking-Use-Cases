Verdict
What Harness² is

It edits the agent's surroundings, never the model

A harness is everything around a model that makes it an agent. Harness² treats that harness as the thing to optimise, using two loops.

Task-level recursion

For the task in front of it, an improver model proposes harness edits, probes them by running the agent on the same task, and composes a refined harness from how the runs behaved differently. It never sees a grader, rubric or answer.

Harnessing-level recursion

After each task, a reflector writes the adopted harness and one evidence-backed lesson into a per-domain library. Later tasks in that domain read the library before proposing.

Parallel or sequential

Parallel explores k general and k domain edits, then composes k finals. Sequential refines through k rounds. Either way a task costs 4k agent rollouts and 3k improver sessions.

The eight editable components map almost one-to-one onto a Claude Code project: c1 to c4 become CLAUDE.md, c5 becomes .claude/agents/, c6 becomes .claude/skills/, c7 stays scripts/, and c8 is the hook layer. That mapping is why the method transfers to Claude Code at all.

Google's release drives OpenCode or Codex on Vertex Gemini against JobBench, LAB and WorkBuddy-Bench, and reports gains of up to 11.5 points from a single step. Interactive diagram: the per-task loop, with source links.

Executors

Claude Code (claude -p, Haiku 5.5), with the harness written as CLAUDE.md, project skills and scripts. A Google ADK agent on local qwen3:8b through Ollama, with four workspace tools and a load_skill tool.

Conditions

Base harness (one sentence). Harness² parallel k=1 over all nine tasks, in order easy to hard within each domain. Sequential k=2 on the data domain (Claude Code only; dropped for ADK to save local GPU time). Karpathy-style autoresearch: four keep-if-better edits on the easy task, scored by the real grader, then frozen.

Measurement

Fresh re-rolls of every adopted or frozen harness, compared with base re-rolls. Transfer from the easy task to medium and hard. Fresh-seed variants to catch memorisation. Hierarchical bootstrap and an exact sign-flip test. Written down before the first treatment run.

Isolation and review before any treatment run

Every model-driven process ran under a macOS sandbox-exec profile with an allow-listed environment. Reads of the grader code, other runs' outputs and credential folders were denied, writes outside the workspace were denied, and web tools were off. Three adversarial reviewers (critical, supportive, neutral) and a security review ran first. Together they caught one silent blocker and seven grader or spec bugs. The full list is in Method lessons.

Using it with Claude Code

Where a harness optimiser earns its cost

Harness² is a search over the files Claude Code already reads. Point it at work your team repeats, and it proposes a CLAUDE.md, skills and scripts, and keeps what changes behaviour. Our whole adapter, covering both executors, sandboxing and auth handling, is about 400 lines, and any agent that reads instructions from files can be plugged in the same way.

Harness² componentClaude Code fileWhat a good edit looks like
system prompt, guardrails, memory, tool guidanceCLAUDE.md"Write a script for any count over a file; never eyeball it"
skills.claude/skills/<n>/SKILL.mdA domain procedure with its own helper script, loaded on demand

subagents.claude/agents/*.mdA reader for large inputs that returns a small table

Team conventions without a test oracle

Finance close, incident write-ups, migration runbooks: work where "correct" lives in a policy document, not in a test. The verifier-free loop is the only option there, and the data-hard task is that shape.

Skills from real sessions

Feed recent session transcripts in as rollouts. The reflector's lesson format (cue, lesson, evidence, confidence) is a ready review template for a skills pull request.

Cheaper or local models

The headroom is with weaker executors. Haiku inside Claude Code was already at ceiling, while qwen3:8b in a plain ADK agent went from mostly failing to three out of three on six of eight tasks. A custom ADK or Agent SDK agent on a small model is where harness edits pay for themselves.

A regression gate for CLAUDE.md

Before merging a prompt or skill change, re-roll it against base at least three times, report pass^k, and run an A/A check. We found a fake +0.11 gain that way.

Per-repo libraries

Harness²'s domain library maps to one library per repository or service. Lessons learned on easy tickets are read first on hard ones.

When not to bother

Already at ceiling (measure first). One-off tasks with no repeating shape. Expecting one harness to cover a whole area: ours did not carry from easy tasks to harder ones. Budgets where four rollouts plus three Sonnet sessions per task (about $0.31 per task in our Claude Code arm) are too much.

A recipe

  1. Collect 10 to 30 representative tasks, with a cheap check for each so you can evaluate. Harness² itself never sees the check.
  2. Re-roll the current setup three or more times per task. Drop tasks that are always perfect or always zero.
  3. Run Harness² k=1 in task order within each area, sandboxed, with no secrets in the agent's environment.
  4. Re-roll each adopted harness three or more times, compare with base outside noise, and re-test on fresh instances to rule out memorisation.
  5. Read the diffs, and grep them for numbers and ids from the task inputs. In our runs the improver wrote computed answers into three of eight skills. Keep the edits that are process (scripts, checks, procedures) and delete every "workspace fact".
  6. Commit to CLAUDE.md and .claude/skills/, and keep the re-roll suite as a regression gate.
