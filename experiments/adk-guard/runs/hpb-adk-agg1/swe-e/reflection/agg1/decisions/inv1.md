There was one rollout, base1. It failed in four ways, and each change below traces to one of them.

- **The agent never fixed the bug.** Its first `write_file` rewrote `src/durations.py` with the same buggy regex, `([hm])`, so the 's' unit was still missing. I added steps 1–2 to `systemprompt.md`. They tell the agent to list every docstring behaviour first, make a real edit, and confirm with a diff that the source changed.
- **The agent misdiagnosed a test-run failure and overwrote the tests.** It ran `python3 tests/test_durations.py` directly, which gives `ModuleNotFoundError`. The test imports `durations` and relies on `conftest.py` to put `src/` on `sys.path`, and that only works under pytest. The agent then clobbered `tests/test_durations.py` three times and added a stray `src/__init__.py`. The final test file contains only the line `from src.durations import parse_duration`. I added step 3 to `systemprompt.md`, which says to run `python3 -m pytest -q tests` from the workspace root. It also says never to edit existing tests or `conftest.py` to get a run to pass, and not to repeat a failing command. `tool_descriptions/tool_guidance.md` now warns that `write_file` overwrites the whole file and must not be used on tests.
- **The agent never made `output/durations.py`.** The run ended mid-debugging with no deliverable. I added step 5 to `systemprompt.md`, which says to `cp` the source to the output path and `diff` the two. I also added `hooks.json` (Stop event) and `scripts/check_output.py`. The hook blocks finishing if `output/*.py` is missing, doesn't compile, differs from the `src/` file of the same name, or if the pytest run fails. It lets the run finish if pytest is not installed or `tests/` is absent. The Stop hook can block finishing at most 3 times, so it can't trap the agent.
- **The existing tests are thin and cover only `1h30m`.** The docstring promises more: case-insensitive units, whitespace, h-m-s order, each unit at most once, and `ValueError` for bad input. I added step 4 to `systemprompt.md`, which has the agent check each of those behaviours itself and append new tests without removing existing ones.

I did not run the new hook in a workspace, only compiled it, and I did not run the new prompt text against a rollout.
